# 事件记录：批量下载全面 403（2026-09-03）

| 项 | 内容 |
| --- | --- |
| 发现时间 | 2026-09-03 |
| 解决时间 | 2026-09-05 |
| 影响 | 批量下载账号作品大面积失败，失败率 45.53% |
| 根因 | 上游内置签名算法 `a_bogus` 已被服务端废弃，且上游已移除其真实计算 |
| 解决 | 启用上游官方外挂扩展点 `encipher.py`，接入抖音官方 WebSecSDK 生成真实签名 |
| 修复提交 | `50e85d5` |
| 结果 | 失败率 45.53% → **0%**（185 账号 / 170 分钟大批量验收） |

---

## 1. 现象

`aweme/post`、`aweme/detail` 大量返回 HTTP 403。

以下操作全部无效：更换 Cookie、更换网络 / IP、回退到提速前基线、降低并发并拉长间隔。

这四项同时失效是关键线索——它一次性排除了身份、网络、本地改动、请求频率四个方向。

## 2. 数据

| 指标 | 正常期（08-28 ~ 09-01） | 故障期（09-03 ~ 09-04） | **修复后（09-05）** |
| --- | --- | --- | --- |
| 目标请求数 | 7,806 | 3,152 | 906 |
| HTTP 403 | 82 | 1,435 | **0** |
| 403 比率 | 1.05% | **45.53%** | **0%** |
| 重试后恢复 | 81 / 81 | 756 / 779 | 无 403 需恢复 |
| `x-secsdk-web-signature` | 0 | 0 | **917（全覆盖）** |

正常期本来就有约 1% 的边缘 403，但全部被重试救回，因此长期无感。故障期错误指纹未变，只是命中概率上升约 43 倍。

最后一行是关键：修复前**包括"正常期"在内，签名从未真正生效**。所谓正常期并非"签名有效"，而是无效签名恰好还能蒙过去；服务端一收紧，比率立刻跳到 45.53%。这也解释了为什么回退到提速前的基线无效——基线同样是零签名。

## 3. 根因

上游作者在 `ef77a70`（2026-08-21 23:29，`perf: 移除参数生成逻辑`）中注释掉了 `a_bogus` 的真实计算，改为返回一个写死的字符串：

```python
def sign(self, query="", data=None, method="", user_agent=USERAGENT, ms_token=""):
    # a_bogus = self._ab.get_value(query, data, method, user_agent=user_agent)
    # return {"a_bogus": a_bogus}
    return {"a_bogus": "dv0Rge7imxQbadKb8cBqy5VU8tnlrBSyhsTobG1PyxKSyq0TDmPc..."}
```

上游 README 同步挂出声明：

> ⚠️ 本项目的加密参数算法已过期失效；为确保项目合法合规，参数算法不再维护，部分功能可能无法正常工作。如需使用，请自行准备加密参数生成代码。

即：**算法失效发生在服务端侧，作者知情并选择不再维护。** 所有请求都带着同一个无效签名，被按 403 拒绝。

### 为什么等新版没用

本仓库基线的 `src/encrypt/aBogus.py` 与上游最新稳定版 **5.7**（`f404781`，2025-08-19）**字节级一致**（两者 SHA-256 均为 `fa811ab8…a155`）。上游 master 后续对 `aBogus.py` 的修改仅为 `get_value` 形参改名并新增 `data` / `user_agent` 入参，核心计算未变。

签名有效性由服务端决定，升级或等新版都不解决问题。必须自备签名来源。

## 4. 解决方案

### 4.1 选型

| 方案 | 结论 |
| --- | --- |
| 调整重试 / msToken / UA / 屏幕几何等参数 | 否。这些都以"`a_bogus` 能算出有效签名"为前提，前提已不成立 |
| 迁移到上游 develop 的新签名方案 | 否。develop 仍在活跃开发，且夹带 `httpx`→`curl_cffi`、构建工具更换、可执行文件改名、`Volume` 路径变更等破坏性改动 |
| **启用官方外挂扩展点 `encipher.py`** | **采用。主干改动最小，可一键回退** |

上游在 `1c41b52`（2026-07-04，`refactor: 实现动态加载外部 Python 代码功能`）引入了该扩展点。本仓库的 fork 分叉点为 `a9f47b5`（2026-06-24），**早于该机制 10 天**，因此额外补了一个最小加载器。

### 4.2 实现

签名来源：抖音官方 `webmssdk.es5.js` 在 Node 的 `vm` 沙箱中运行（伪造 `navigator` / `location` / `window` / `atob` / `btoa`），无头产出 32 字符的 `x-secsdk-web-signature`。Python 侧经 JSPyBridge（`javascript==1!1.2.6`）调用。

**新增**

| 文件 | 说明 |
| --- | --- |
| `encipher.py` | 外挂签名主体（根目录，348 行）。导出 `DouYinParams` / `TikTokParams` |
| `src/tools/external_params.py` | 最小加载器（72 行），三级降级，输出纯 ASCII 以避免 Windows GBK 乱码 |
| `static/js/{webmssdk.es5,sdk-glue,runtime_bundler_34,environment}.js` | SDK 及运行时胶水 |

**修改**

| 文件 | 改动 |
| --- | --- |
| `src/interface/template.py` | `deal_url_params` 增加外部签名分支；透传 `url` |
| `src/application/TikTokDownloader.py` | 启动时打印外挂签名状态 |
| `src/tools/__init__.py` | 导出 `load_external_douyin_params` |
| `.github/workflows/*.yml` | 增加 `--collect-all javascript` |
| `requirements.txt` / `pyproject.toml` | 增加 `javascript==1!1.2.6` |

主干核心改动仅此一处：

```python
def deal_url_params(self, params: dict, method="GET", url: str = "", **kwargs) -> str:
    if params:
        params = urlencode(params, safe="=", quote_via=quote)
        # 优先使用根目录 encipher.py 提供的外部签名实现；
        # 文件不存在时 external 为 None，行为与原始代码完全一致。
        if external := load_external_douyin_params():
            return external.sign_url(url, params, None, method,
                user_agent=self.headers.get("User-Agent", USERAGENT))
        params += f"&a_bogus={self.ab.get_value(params, method)}"
        return params
    return ""
```

TikTok 路径不受影响（`APITikTok.deal_url_params` 带 `**kwargs`，新增的 `url=` 被安全吸收）。

### 4.3 降级与回退

1. `encipher.py` 不存在 → 加载器返回 `None` → 走原生 `a_bogus`，行为与改动前完全一致
2. Node 缺失或 SDK 加载失败 → 退回 `a_bogus`
3. 单次签名抛异常 → 返回空串，交由上层重试

**回退方式：删除 `encipher.py`。** 该文件刻意不打进构建产物，正是为此。

### 终轮大批量实测（2026-09-05 03:50 → 06:39）

| 指标 | 数值 |
| --- | --- |
| 日志规模 | 86,851,878 字节 / 179,525 行 |
| 计划账号 / 实际开始 | 186 / 185 |
| 目标请求（`aweme/post`） | 906 |
| **HTTP 403** | **0** |
| 响应码构成 | `200` × 917、`206` × 18,922，别无其他 |
| 重试 | 6（4 次传输断流 + 2 次 CDN 404，均非 403 触发） |
| `x-secsdk-web-signature` | **917 / 917（100%）** |
| `im/user/info/` 请求 | 11（批量生效） |
| `batch_fallback` 回退 | 0 |
| 请求总数校验 | 906 + 11 = 917 = `Params` 行数 = `200` 响应数 |

两点比"零 403"更强的证据：

1. **签名覆盖率严格 917 : 917**，与 `[INFO]:  Params` 行一一对应，说明没有任何请求走了降级路径——不是"碰巧没被拒"，而是签名链路全程在工作。`a_bogus` 计数同为 917 属正常：`sign_url` 刻意保留它再追加签名（`encipher.py:323`、`:346`），判断签名是否生效只看 `x-secsdk-web-signature`。
2. **响应码集合里根本没有 403**。日志中另有 4,863 行含字符串"403"，全部是作品 ID 与哈希片段里的数字巧合（如 `24ed6b88403c18a`），与状态码无关。此处用逐行统计 `Response Code:` 与关键字计数两条独立路径交叉验证，避免把"没统计到"误读成"没发生"。

### 关于"附加异常"的说明

管理程序看板显示"附加异常 10"，与 403 无关。下表由引擎日志逐行统计得出：

| 类型 | 日志级别 | 涉及账号 | 涉及作品 | 触发重试 | 性质 |
| --- | --- | --- | --- | --- | --- |
| 视频下载地址解析失败 | ERROR | 7 | 36 | 否 | 返回 JSON 中播放地址字段为空 |
| 提取文件下载地址失败 | ERROR | 1 | 1 | 否 | 同上，另一条代码路径（"跳过下载"） |
| 下载中断 | WARNING | 3 | 4 | 是 | 传输中途断流 |
| 响应码异常 404 | WARNING | 1 | 2 | 是 | CDN 上源文件已不存在 |
| **合计（账号去重）** | — | **11** | **43** | — | — |

与日志总量闭合：ERROR 37 = 36 + 1；WARNING 14 = 4 + 2 + 6（重试）+ 2（私密账号）。账号去重后为 11 而非 12——1 个账号同时出现"解析失败"与"下载中断"。

**这四类的失败点全部在签名之后。** `aweme/post` 成功返回 200 并拿到作品列表，失败发生在其后：前两类（37 个作品）连地址都没拿到（`video.play_addr.url_list` 为空）；后两类（6 个作品）地址拿到了但传输失败，各触发 1 次重试，**正好构成"重试 6 次"的全部来源**（4 次断流 + 2 次 404）。

分层区别：403 是**接口层**拒绝，拿不到列表，账号零产出；这里是**内容层**缺失，列表拿到了，个别作品文件没了。那 2 次 404 是**文件级**失败（WARNING `响应码异常`，URL 为 `aweme/v1/play/?video_id=…`，集中在同一账号的 2 个作品上），语义为"视频文件不存在"，而非"无权限"。成因在平台侧（作者设为仅自己可见、下架、转码资源过期），无需处理。

**另有 2 次"私密账号"警告**：请求正常返回，服务端明确告知需登录且需关注该账号——属**业务层**拒绝，与签名层、接口层均不同。两个账号都在"实际开始 185"之内，因此不是"计划 186 / 实际 185"里差的那 1 个。

看板的"完整性：不完整"与"可靠性：不可靠"同源于"计划 186 / 实际开始 185"中差的那 1 个账号（归类为"账号身份校验未通过"）。该账号未启动，不是跑失败；判定口径偏保守，只要 1 个账号未能明确归类即标记整批不可靠。**"身份校验"与签名无关**——签名走 `x-secsdk-web-signature`，身份走 Cookie。

上表为日志侧独立拆解，去重后 11 个账号与看板的"附加异常 10"差 1，无法逐项对齐；"附加异常"的确切定义以实际运行的管理程序版本为准。

附带收益：签名按秒级时间戳自动刷新，**"重试时复用同一签名"这一长期缺陷随之消失**，且未改动任何重试逻辑。

## 6. 部署要求

1. **目标机需 Node.js ≥ 18。** 缺失时签名会静默退回失效的 `a_bogus`，403 会重现。
2. 构建工作流**必须**保留 `--collect-all javascript`。JSPyBridge 以包数据形式携带 `javascript/js/*.js`，PyInstaller 默认不收，缺失会导致冻结版启动即崩。
3. 安装后需手动将 `encipher.py` 放到 `main.exe` 同级目录。
4. 运行前确认启动横幅：

```
外挂签名代码 encipher.py: 已加载  WebSign: 已启用
```

显示"未加载"或"不可用"时**不要**执行批量任务。

## 7. 边界说明

- **403 的消失来自签名修复，与此前两阶段请求量优化无因果关系。** 两阶段优化（长链接本地解析、批量 Info）降低的是频率类压力；身份类风控未受影响。不应据此调小请求间隔或关闭 `suspend()`。
- `wait()`（均值 6 秒随机间隔）与 `suspend()`（默认 50 个账号休息 150 秒）在本次修复中**完整保留**（改动范围见 §4.2，二者未被触及）。注意 `suspend()` 走 `console.print`，只打控制台不写日志，因此**日志里查不到它的触发记录**——按账号数推算，不要据此认为节流失效。
- 排障统计请使用 `docs/log-sanitize/sanitize_log.py`（白名单设计，只输出聚合计数，日志正文不外发；用法见同目录 `README.md`）。**引擎日志位于 `<引擎目录>\_internal\Volume\Log\`**，由 `src/custom/internal.py` 的 `PROJECT_ROOT` 决定，不在引擎根目录；`Volume/settings.json` 里的 `root` 是下载目录，与日志无关。
- 未同步上游 master：其签名状态更差（写死占位符），并夹带破坏性改动。
- `webmssdk.es5.js` 属字节跳动专有代码，无开源许可，与本仓库 GPL-3.0 存在冲突。上游仅在 develop 分支携带，master 与 release 均不含。使用者需自行评估合规风险。
